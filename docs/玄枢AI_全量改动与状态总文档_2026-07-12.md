## 一、软件基线（最初状态 · v10.1.1 · 2026-06-28）

v10.1.1 是本次工作开始前的交付版，由标准 SOP（PRD→架构→实现→QA）产出：

- **架构**：高见远 5 任务架构设计 + 时序图
- **实现**：寇豆码 27 文件修改/新建，`IS_PASS: YES`
- **QA**：严过关 15 组 40+ 检查点 100% PASS

### 基线已具备的能力
1. **5 个 P0 致命 Bug 全部修复**
   - 联网搜索代理生效（`search/index.ts` dispatcher）
   - 语音克隆真集成（OpenVoice 256 维 + 真实 TTS）
   - 模型空闲误卸载修复（`lastUsed` + 15min IDLE）

   - 首页模型对话可用（`done→finally` + `Map<sessionId>` + `updateModelUsage`）
2. **新增功能**：visual-agent 完整版（截图→识别→执行→验证闭环 + 85 条常识规则）、SGLang 预集成（离线 wheel 包 + 首次启动自动安装）、OpenVoice 真语音克隆（256 维 embedding + 5 预置音色）、模型下载后自动注册+加载、10 页面 UI 布局修复、桌面太极图标修正。

### 基线技术栈与架构
- **技术栈**：Electron 32 + React 18 + TypeScript + Zustand + Tailwind v4
- **推理**：node-llama-cpp（CPU）/ SGLang 端口 30000（`--host 127.0.0.1`，GPU）/ Ollama / OpenAI
- **无 FastAPI 后端**；Python 3.12 仅作子进程工具调用
- **持久化**：electron-store + better-sqlite3 + JSON 文件
- **打包**：electron-builder NSIS + 自定义 `installer.nsi`
- **规模**：主进程 30+ 模块、渲染端 10 页面 + 6 Zustand store、约 200 个 IPC 通道

### 基线已知「暗坑」（本阶段才暴露/根治）
- 7B 模型注册时 `gpuLayers:99` 在注册循环中被丢失 → 一直走纯 CPU（未真正上 GPU）
- 14B 的 `gpuLayers:22` 因 `cpu-engine.ts` 的 `getLlama()` 无 `gpu` 参数 → 历来是「废设」，实际纯 CPU

- SGLang 在原生 Windows **无可用 wheel**（仅 manylinux），基线「首次启动自动安装」在 Windows 上根本装不上

## 二、本阶段全部改动时间线

### 阶段 1 · SGLang WSL 集成探索（07-11 19:xx）
- **起因**：SGLang 原生 Windows 无法安装（PyPI 仅 manylinux wheel），用户拍板改走 WSL2。
- **操作**：建立团队 `software-sglang-wsl`；架构师出 WSL 集成设计；工程师改 `python.ts` / `sglang.ipc.ts` / `install_sglang_offline.py`；QA 补测试。
- **关键发现**：WSL2 默认把内部端口转发到 Windows localhost，现有 `127.0.0.1:30000` HTTP 客户端代码 **零改动** 即可复用；仅需改拉起方式（`wsl.exe -e python3 -m sglang.launch_server` + 模型路径翻译为 `/mnt/e/...`）。
- **离线预打包就绪**：`electron-builder.yml` 已 `extraResources: resources/sglang→sglang`；`resources/sglang/` 已有 `install_sglang_offline.py`、`requirements-offline.txt`、空 `wheels/`。

### 阶段 2 · 本机驱动与 CUDA 核查（07-11 19:5x）
- **实跑诊断**：`nvidia-smi` → 驱动 610.74、CUDA UMD 13.3、RTX 3060 Laptop 6GB、状态 OK；`wsl --list` → 未装 WSL。
- **结论**：驱动完全支持 WSL2 GPU 透传；唯一限制是 6GB 显存，SGLang 跑 7B q4 约 4-5GB 可挤下，14B 必 OOM。
- **显存约束落地**：`sglang.ipc.ts:27` `sglangMemFraction` 由 `'0.88'` → `'0.80'`；`model-manager/index.ts` 新增 SGLang 兼容性门控（quality 档 / >5GB 跳过 SGLang 直走 CPU）。

### 阶段 3 · 用户嫌 WSL 麻烦 → SGLang 纯可选 + 静默回退 CPU（07-11 21:3x）
- **沙箱实测**：`wsl --install` 失败（非管理员 + 网络 502）→ 确认 WSL 安装只能用户本机管理员自行跑，AI 代劳不了。
- **决策**：SGLang 在 6GB 卡上 GPU 加速意义不大（14B 必 CPU，7B CPU 也能跑），改为**纯可选**，删除所有「没 WSL 就弹窗催装」逻辑：
  - `python.ts:479-489` `ensureSGLang()` 非 WSL 分支：删弹窗 → 静默 `return false`
  - `model-manager/index.ts:299-309` 非 WSL 分支：删弹窗 → 静默回退 CPU（仅 `console.log`）
  - WSL 代码路径**保留**，用户日后想提速装 WSL 仍可用。
- **下载位置约束**：代码下载只往 E 盘（`resources/sglang/wheels/`、`resources/models/`）。

### 阶段 4 · 国内模型下载源定位与模型库整理（07-11 全天）
- **源核查**：huggingface.co 经代理返回 502 → 不可达；hf-mirror 上 bartowski 仓库实测 404。最终确认 **ModelScope 直链**（`modelscope.cn/.../resolve/master/...` + `curl -L` 跟 302 到阿里云 OSS）最稳，约 3MB/s。
- **质量档 14B 下载**：`internvl2.5-14b.gguf`（8.51GB）+ `mmproj-InternVL3_5-14B-f16.gguf`（705MB），经 ModelScope 后台下载。
- **打包策略变更**：用户最终拍板 **全部模型打进安装包**（自包含 ~40GB，装完即用），放弃「外置 E:\模型\ 引用」。已把 14B 两件套与纯文本 14B 搬回 `resources/models/`。

### 阶段 5 · 模型最终整理 + 代码注销 + 路径修正（07-11 18:xx）
- **文本 7B / deepseek 注销**：从 `index.ts` 模型注册表、priorityOrder、下载目录三处全部移除（文件已删）。
- **视觉 7B 重复副本清理**：删除与已注册 `qwen2-vl-7b.gguf` 同模型异名的副本，省 ~4.68GB 打包体积。
- **最终版模型固定为 5 个**（用户可见）：视觉14B-Q4、mmproj-视觉14B-f16、视觉7B-Q4、mmproj-视觉7B-f16、向量检索-nomic-embed。
- **缺模块真相（非缺失，是路径错）**：`index.ts:223` 原 `require('./vision/visual-queue')`，但导出 `visualQueue` 的文件是根目录 `src/main/visual-queue.ts`；修正为 `require('./visual-queue')` 即解决（tsc 零新增错误）。

### 阶段 6 · 7B 纯 GPU / 14B 分层 + Vulkan 后端 + 真机实测（07-11 21:4x）
- **模型其实在盘上**：`resources/models/` 已有 `qwen2-vl-7b.gguf`(4.46G)、`internvl2.5-14b.gguf`(8.12G)、`nomic-embed.gguf` 等。
- **GPU 后端实测**：
  - `getLlama({gpu:'cuda'})` → 预编译 CUDA 二进制「not compatible」→ 回退源码编译（需 CUDA toolkit+MSVC，本机无）→ **CUDA 不可行**。
  - `getLlama({gpu:'vulkan'})` → 3 秒返回 `gpu="vulkan"`，**Vulkan 预编译兼容、离线可用**（NVIDIA 驱动自带 Vulkan ICD，无需 CUDA toolkit）→ 这是本机 GPU 之路。
- **满足用户硬约束（gpuLayers 固定值不改）的代码改动**：
  - `index.ts:273` `qwen2-vl-7b` 加 `gpuLayers:99`（全层上 GPU = 纯 GPU）
  - `model-manager/index.ts` `tryCpuLoad` 透传 `gpuLayers: model.gpuLayers ?? 0`（此前默认路径不读 gpuLayers → 纯 CPU，已修）
  - `cpu-engine.ts` `getLlama()` → `getResolvedLlama()`：优先 `getLlama({gpu:'vulkan'})`，失败静默回退 CPU（全局缓存）
  - 14B `gpuLayers:22` 与 `loadQualityModel` 逻辑**原样未动**
- **真实推理实测**（应用同款 node-llama-cpp harness）：7B 纯 GPU → 显存 1520→4630MB（暴涨 ~3.1GB）✅；14B 分层(22 层) 因 6GB 卡 KV cache 装不下 → **OOM（真 bug R1）**。

### 阶段 7 · 环境自适应（07-12，一次性高质量完成）
- **新增 `src/main/runtime/hardware.ts`**：`detectHardware()`（nvidia-smi 探测 GPU/显存，失败安全回退 `hasDGPU:false`，不阻断启动）+ `resolveModelRuntime(model,hw)` 按显存分档推导 `gpuLayers/contextSize/available`。
- **阈值策略**：
  - 7B：有独显且 ≥6GB → 上 GPU（`gpuLayers=99`）；否则回退 CPU(0)
  - 14B（quality 档）：仅当显存 ≥8GB 才 `available`（`gpuLayers=22` 原样透传）；否则 `available:false` + reason 提示禁用（**根治 6GB 卡 14B OOM**）
  - 无独显 → 全 CPU
- **串联改动**：`index.ts` 注册循环补传 `gpuLayers/tier`（根因修复：此前 7B 的 99 丢失）；`model-manager` 的 `tryCpuLoad/loadQualityModel` 改用 `resolveModelRuntime` 门禁 + 新增 `getModelRuntimeInfo()` + IPC `model:manager:runtime`；`Model/index.tsx` 加硬件条 + 不可用模型灰显禁用。
- **硬约束遵守**：grep 核实 `index.ts:273/276` 仍 `99/22`，全程未改。

## 三、改进思路汇总（「为什么这么做」）

| # | 改动 | 改进思路 / 内核 |
|---|------|----------------|
| 1 | SGLang 纯可选 + 静默回退 CPU | 6GB 卡上 GPU 加速意义不大（14B 必 CPU、7B CPU 也能跑）；WSL 安装门槛高（管理员+重启+设账号），不应阻塞主流程；保留 WSL 代码路径作未来提速选项，但默认零安装零重启即用。 |
| 2 | 国内模型下载源 | huggingface.co 国内被墙；经实测锁定 ModelScope 直链 + `curl -L` 跟重定向，避开 404 的 hf-mirror 仓库。 |
| 3 | 全部模型打进安装包 | 用户要「简单」——自包含安装包装完即用，比「外置 E:\模型\ 引用」更省心，代价是安装包体积增至 ~16GB+。 |
| 4 | 注销冗余模型 | 未用模型（deepseek、qwen2.5-7b、纯文本 14B、视觉 7B 重复副本）既占打包体积又会被 auto-scan 误注册，注销后注册表只留 2 个真用模型，干净可控。 |
| 5 | visual-queue 路径修正 | 不是「缺模块」，是 `require` 路径写错（指向不存在的 `vision/` 子目录）；改为根目录引用即可，不引入新依赖。 |
| 6 | 7B 纯 GPU / 14B 分层生效 | 根因双保险：① 注册循环丢 `gpuLayers` → 补传；② `getLlama()` 无 `gpu` 参数使 22 层「废设」→ 改 Vulkan 后端。硬约束 `99/22` 数值全程不改，只修「让数值真正生效」的通道。 |
| 7 | Vulkan 而非 CUDA | CUDA 预编译二进制与本机不兼容、源码编译需 toolkit+MSVC（无）；Vulkan 由 NVIDIA 驱动自带 ICD 提供，预编译即兼容、离线可用——是这台 3060 的 GPU 正解。 |
| 8 | 环境自适应（hardware.ts） | 不同电脑（无独显 / 显存 <6G / ≥8G）需要不同路由；用 `nvidia-smi` 运行时探测，按显存分档决定 gpuLayers/contextSize/可用性；「<8GB 禁用 14B」从策略层根治 OOM，而非靠用户手动规避。 |
| 9 | UI A–G 规范化 | 按既定 UI 规范逐项落地（输入框居中、书法问候、16px、折叠面板、Markdown 卡片、圆形发送、占位面板），目标是对齐产品级体验。 |
| 10 | 预览错配教训 | 预览 HTML 必须严格对齐真应用 CSS 变量；大改 UI 前应先出小样让用户确认；用户偏好增量微调而非整页重写。 |
