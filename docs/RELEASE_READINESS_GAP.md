# 玄枢AI 发布就绪度差距清单

> **⚠️ 场景已修正（2026-08-24）**：本 App 定位为**个人私人使用，不发布、不更新**。
> 因此原"发布级"差距清单中，凡涉及对外分发/多用户/上架审查的项（代码签名、SmartScreen、隐私政策、更新通道、CI/CD、多语言、无障碍、品牌名）**全部不再适用**。
> 真正的结论收敛为下面「个人自用版」这一段。

---

## 个人自用版结论（最终有效）

**功能已经够用，离"放心用"只剩一件事：数据备份。**

### 真正还差的（个人自用，按重要性）

| # | 项 | 现状 | 影响 |
|---|---|---|---|
| 1 | **聊天记录无导出/备份** | 记录存在 localStorage，全库无任何导出功能 | 清缓存/卸载/磁盘故障 = 记录全丢。个人用户最痛的点 |
| 2 | 记忆/知识库虽有 sqlite，但无统一备份 | `userData/data/memories.db` 等 | 同上，分散在多个文件，无一键备份 |
| 3 | 2 个测试文件损坏 | 引用不存在的模块 / electron 未 mock | 不影响运行，但无法自动回归 |

### 已确认可接受（个人自用无需处理）

- `requireAdministrator` 提权：个人机器、自己就是管理员，可接受
- 代码签名 / SmartScreen：自己装自己用，无感
- 隐私政策 / 更新通道 / CI / 多语言 / 浅色主题 / 无障碍 / 品牌名：单人自用全部无关

### 已修复且依然有价值的安全项（上一轮完成，保留）

命令注入（插件引擎 / PowerShell）、移动通道配对码泄露、暴力破解防护、视觉代理确认门、聊天存储 localStorage 守卫、监听器泄漏——这些对个人用户同样是真实风险（尤其若连了手机/局域网）。

---

> 一句话：**个人自用场景下，工作量从「3-4 个月」缩水到「约 1 周」，核心就一件事——加个数据导出/备份。** 其余"发布级"标准不再构成障碍。

## 附：原"发布级"评估（已作废，仅存档）

> 评估日期：2026-08-24（作废前）
> 结论：**核心功能已跑通、构建通过，处于"内部可用"状态；但距"大厂产品级正式发布"仍有显著差距。**
> 按「内部测试版 → 公测 Beta → 正式发布」三级里程碑量化，当前约完成 **40%**，还需补齐 **P0（安全硬门槛）+ P1（质量硬门槛）+ P2（产品打磨）+ 合规** 四个板块。

## 一、安全基线（发布硬门槛，不修完不能发）

| 优先级 | 问题 | 当前状态 | 为什么挡发布 |
|---|---|---|---|
| 🔴 P0 | 全应用以管理员权限运行（`requireAdministrator`） | `electron-builder.yml:38` | 无 UAC 边界，任一注入漏洞 = 系统级接管，安全审计必挂 |
| 🔴 P0 | 代码签名私钥（`.pfx`）在仓库里 | `resources/cert/xuanshu-root.pfx` | 私钥泄露，攻击者可仿冒/篡改签名，供应链风险 |
| 🔴 P0 | 自签名证书触发 SmartScreen 拦截 | 依赖 `generate-cert.ps1` | 用户首次运行看到红色"危险"警告，转化率崩 |
| 🟠 P0 | preload 通用 `invoke` 无运行时通道白名单 | `preload/index.ts:555` | 渲染层一旦被 XSS，可调用全部 500+ 特权通道 |
| 🟠 P0 | IPC 无 zod 参数校验 | 全部 handler | `type-text`/`execute-command` 等参数内容零校验 |
| 🟠 P1 | 控制类操作缺统一确认门 + 审计日志 | `desktop-automation`、`plugin:execute` | `type-text`/`send-keys`/`plugin:execute` 仍无确认；无操作审计落盘 |
| 🟠 P1 | 屏幕/相机/麦克风/剪贴板无逐次授权 | `system-control.ipc.ts` 等 | 隐私合规风险（尤其 AIGC 备案后监管更严） |
| 🟡 P1 | IPC sender 白名单仅进程级、主 frame URL 不校验 | `utils/ipc-guard.ts` | 主窗口被导航到恶意页仍可 invoke 全部通道 |

## 二、工程质量（发布硬门槛）

| 优先级 | 问题 | 当前状态 | 差距量化 |
|---|---|---|---|
| 🔴 P1 | **测试覆盖率极低** | 源码 205 个 `.ts/.tsx`，测试仅 16 个文件 | 文件覆盖率约 7.8%，核心链路（桌面自动化、视觉代理、移动通道、IPC）几乎零测试 |
| 🔴 P1 | **2 个测试文件本身已坏** | `tests/core/split-text.test.ts`、`tests/services/resilience.test.ts` | 一个引用了不存在的 `resilience` 模块，一个 electron `app` 未 mock。CI 红灯无法拦截回归 |
| 🟠 P1 | 无 CI/CD 流水线 | 仅 `.github/` 有雏形 | 无自动化构建/测试/签名/发布，全靠手动 |
| 🟠 P1 | lint 数百个历史告警未治理 | `any`/`require`/`curly` 遍布 | 代码质量基线不达标，无法设 CI 门禁 |
| 🟡 P2 | 流式写入读源不一致、陈旧闭包 | `Home/index.tsx`、`chatStore` | 切换会话时可能丢流式内容 |
| 🟡 P2 | 仅暗色主题 + 双套 token 混用 | `globals.css` vs `theme.ts` | 主题切换会视觉撕裂 |

| 优先级 | 问题 | 当前状态 |

## 五、量化结论

| 里程碑 | 还差什么 | 估算剩余工作量 |
|---|---|---|
| **内部测试版**（团队内/亲友可用） | 修 P0 安全 3 项 + 补隐私政策 | ~1–2 周 |
| **公测 Beta**（对外小范围） | 再补 zod 校验、确认门、测试覆盖率到 40%+、CI、正式签名 | ~4–6 周 |
| **正式产品级发布** | 全部 P0+P1+P2 + 合规 + i18n + 浅色主题 + 崩溃上报 + 更新通道 | **2–3 个月**（多人团队），单人 3–4 个月 |

> 一句话：**功能已经"能用"，但"能发"还差安全、测试、合规三块硬骨头。** 最优先的三件事是——① 降权 + 移除私钥 + 换正式签名；② 补隐私政策；③ 修坏掉的测试并大幅提覆盖率。
