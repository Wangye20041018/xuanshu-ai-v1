## 0. 最高准则（一句话）

**玄枢是"有工程能力的本地算力终端"，不是"假装像人的聊天软件"。**
视觉向 Trae 这类成熟桌面效率工具看齐：干净、克制、专业、高效、可掌控。**不拟人、不炫技、不堆光效。** 判断每一像素去留的标准：它是否让"用户对电脑正在做什么"更清楚、更可控。

## 1. Trae 实况视觉拆解（从抓帧逐区实测）

### 1.1 整体骨架
- **单栏任务流为绝对核心**：窄窗口（853 宽）下无明显粗侧栏，主内容是一条从上到下的"叙述 → 动作过程 → 叙述 → 步骤清单"纵向流。
- 层级仅靠**背景明度差**区分，几乎不使用描边/分割线/投影。
- 纵向留白充足、信息密度低，阅读节奏松弛但信息清晰。

### 1.2 顶栏（极简）
- 高度约 **40px**，深色实底，无渐变、无边框（或极弱 1px 底线）。
- 左侧仅两个 **18px 线性图标**（视图切换、搜索），中间是文字菜单"编辑(E) 帮助(H)"，右侧为窗口控制。
- 没有 Logo 大字、没有品牌色条、没有标题装饰。

### 1.3 任务卡片容器
- 左上角一个**线性对话气泡图标 + "新任务"**（约 15px，常规偏中字重），右侧"…"。
- 卡片圆角约 **12px**，背景比页面底**只亮一档**，无重描边、无辉光。

### 1.4 叙述文本（Agent 的话）
- 亮白、约 **15–16px**、行高约 **1.7**、左对齐、无气泡、无边框（AI 内容**不装在气泡里**）。
- 段落之间靠行距自然分隔。

### 1.5 动作过程行（= 本任务 UI-2 的直接范本）
- 灰色小字（约 **13px**，中灰），格式为"**已读取 1 个文件 〉**""**已执行 3 条命令 〉**""**已读取 1 个文件，执行 1 条命令 〉**"。
- **聚合计数、实时累加**（不是把每条原始日志都铺开）；右侧一个 `〉` chevron 提示可展开；点击展开原始明细。
- 行高紧凑、与上下叙述留白分明，视觉权重明显低于正文。

### 1.6 任务步骤清单（= 本任务 UI-1 的直接范本）
每一行 = **状态圆点 + 步骤标题（+ 括号补充）+ 右侧 chevron**，纵向排列：
| 状态 | 圆点形态（实测） | 颜色 |
|---|---|---|
| 待执行 pending | 空心灰圆 `○` | 中灰 `#7e7e88` 一档 |
| 进行中 running | 蓝色**旋转/脉冲**圆点 `◐`（spinner） | 蓝 `#4b8ef1` 附近 |
| 已完成 done | 绿色实心圆 + 对勾 `✓`（描边圆） | 绿 `#3fb97b/#34d399` 附近 |
| 失败 failed | 红色 `✗` | 红 `#ef4444` 附近 |
- 步骤标题约 14px；括号补充用中灰、常规字重；整行可点击展开详情；失败步骤整行偏红并显示原因。
- 步骤之间用**极细竖向引导线**或纯留白串联，不使用卡片堆叠/进度条/发光。

### 1.7 配色（深色，抓帧取色近似值）
- 页面底 `#1b1c1e`，卡片/抬升面 `#232427`，再高一档 `#2a2b2f`。
- 正文 `#e9e9eb`，次文字 `#9aa0a8`，弱文字 `#6b7078`。
- 语义：进行蓝 `#4b8ef1`、成功绿 `#3fb97b`、失败红 `#ef4444`、警示琥珀 `#f59e0b`。
- **中性、低饱和、无品牌彩色、无紫蓝渐变、无发光**。

### 1.8 动效
- 仅用于"状态变化"：圆点 spinner 匀速旋转、步骤出现/展开用 150–250ms 的轻淡入 + 微小位移（y 2–4px）。
- 缓动统一为偏 decelerate（对应玄枢既有 `cubic-bezier(0.2,0,0,1)` / `[0.16,1,0.3,1]`）。**无弹跳、无辉光脉冲、无缩放炫技。**

## 2. 玄枢现状基线（实读 `styles/globals.css` 等，逐 token 盘点）

> 好消息：玄枢现有底子就是 **Neutral Dark 中性深色**，色板与 Trae 几乎同调；本次是"**校准层级 + 换组件形态 + 补任务时间线**"，不是推翻重做。

### 2.1 现有色板（深色默认，`:root`）
| 类别 | 现有 token → 值 | 与 Trae 关系 |
|---|---|---|
| 背景 | `--bg-base #1a1a1c` / `--bg-surface #202022` / `--bg-elevated #28282a` / `--bg-overlay #303032` / `--bg-card rgba(40,40,42,.8)` | 基本一致，**层级差偏小**（base→surface 仅差一档明度，Trae 卡片更"抬得起"） |
| 悬停/按下 | `--bg-hover 白.06` / `--bg-active 白.08` / `--bg-input 白.04` | 可直接沿用 |
| 边框 | subtle 白.04 / default 白.07 / strong 白.10 / strong-hover 白.14 | Trae 更弱，倾向**默认无边框、仅 hover/必要时 subtle** |
| 文本 | heading `#ececed` / primary `#e8e8ec` / secondary `#a6a6b0` / tertiary `#7e7e88` / disabled `#4a4a52` | 高度一致，沿用 |
| 中性主色 | accent/brand `#b0b0ba`（银灰，无品牌色） | 符合"克制"，保留 |
| 语义 | success `#10b981`、success-alt `#22c55e`、danger `#d4706a`(偏柔)、danger-alt `#ef4444`、warning `#f59e0b`、info `#06b6d4`、HEX blue `#3b82f6`、violet `#8b5cf6` | **缺统一的"运行状态色"语义层**（见 §3.2），且进行中现在多用银灰，Trae 用蓝 |

### 2.2 现有字号阶梯（偏小，基准 13px）
`--text-xs 10 / sm 12 / base 13 / lg 14 / xl 15 / 2xl 20 / 3xl 22 / 4xl 28 / display 34`
行高：none 1.1 / tight 1.25 / snug 1.4 / normal 1.55 / relaxed 1.7。
- 问题：**全局基准字号偏小（13px）、过程/辅助文字甚至用到 10–11px**，与 Trae"正文 15–16、过程 13"的松弛感相反。

### 2.3 圆角 / 间距 / 阴影 / 动效
- 圆角：xs2/sm4/md6/lg8/xl10/2xl12/3xl14/card8/tag4/full；并有 `data-radius` sharp/default/rounded 三档整体覆盖。
- 间距（4px 栅格）：space-1 2 / 2 4 / 3 6 / 4 8 / 5 12 / 6 16 / 8 20 / 10 24 / 12 28 / 14 32 / 16 40。
- 阴影偏重：sm `0 2px 4px rgba(0,0,0,.3)` … xl `0 16px 40px rgba(0,0,0,.7)`，另有 `--inset-hi*` 内高光、`--accent-glow*` 辉光。
- 动效：ease-out `cubic-bezier(0.2,0,0,1)`、spring、fast120/normal200/slow350；Framer Motion 全局惯用 `[0.16,1,0.3,1]`。
- 字体：`--font-ui "Work Sans","Noto Sans SC","PingFang SC"`；**标题/展示用 `--font-display "Playfair Display","Noto Serif SC" 衬线体`**；mono `JetBrains Mono`。

### 2.4 现有布局尺寸
- `.app-layout` flex 横排 100vw/h；`.app-sidebar` 宽 240 / 折叠 64（≤1300→200，≤1200→64）；`.app-titlebar` 高 40；`.app-statusbar` 高 24；`.app-content` flex 纵向；`.page-container` 内边距 24/28、`--content-max 1120`。
- 滚动条已很细（5px、thumb 白.08），方向正确，沿用。
- 按钮类：`.btn` + 尺寸 s26/m30/g34、sm28/md32/lg36，variant：primary/secondary/ghost/danger。

### 2.5 现状中与"Trae 观感"冲突的点（本次要收敛）
1. **衬线展示字体 Playfair Display**（启动诊断标题、HomeHeader 等）= 文雅拟人感，与工程工具气质冲突 → UI 字体全面回归无衬线，标题不再用衬线。
2. **辉光/内高光/玻璃渐变**：输入框 `linear-gradient + inset-hi-strong + accent-glow`、历史抽屉"160deg 深色渐变 + 3px 边框 + blur20"、圆点 `box-shadow:0 0 8px 色` 等 → 去发光、去渐变，改纯色 + 明度差。
3. **进度条/百分比/大卡片**承载任务过程（TaskCard、TaskProgressOverlay）→ 改为 Trae 式圆点时间线；其中 `TaskProgressOverlay` 已是**不订阅事件的空壳（代码注释明示 task:*/scheduler:* 已废弃）**。
4. **字号过小、辅助文字 10–11px 偏多**、过程信息密度过高（AgentRunner 步骤回放 10–11px）。
5. **侧栏 240px 常驻且分组+文字偏强**，主工作区不够"单栏聚焦"。
6. 存在 `data-bg='gradient'` 紫蓝深空渐变主题 → 与定位冲突，默认与推荐一律 `dark`，渐变不作为主风格。

## 3. 目标设计 Token（落地时改 `globals.css` `:root`，全部走 CSS 变量，组件不写死颜色）

> 原则：**能复用现有变量就复用**；新增的只补"任务运行状态语义层"和"单栏流尺度"。下列为目标值，落地以"新增/覆盖"标注，不破坏 light 主题与 data-radius 机制。

### 3.1 中性表面（在现有基础上把"抬升差"拉开一点点，仍低对比）
```css
/* 校准建议（深色 dark） */
--bg-base:     #1a1b1d;   /* 由 #1a1a1c 微冷化，贴近 Trae #1b1c1e */
--bg-surface:  #202124;
--bg-elevated: #27282c;   /* 卡片：比 base 亮一档，够"抬得起" */
--bg-overlay:  #2f3035;
--bg-card:     rgba(39,40,44,0.86);
--bg-input:    rgba(255,255,255,0.045);
--bg-hover:    rgba(255,255,255,0.06);
--bg-active:   rgba(255,255,255,0.09);
/* 边框整体再弱化：默认无框，需要分隔才用 subtle */
--border-subtle:  rgba(255,255,255,0.05);
--border-default: rgba(255,255,255,0.08);
```
文本维持现值（已与 Trae 同调）。

### 3.2 【新增核心】任务运行状态语义色（UI-1 步骤 / UI-2 工具行 共用唯一真源）
```css
/* 四态：pending / running / done / failed */
--status-pending: #7e7e88;            /* 空心灰圆，沿用 text-tertiary */
--status-running: #4b8ef1;           /* Trae 进行蓝（区别于银灰 brand） */
--status-running-dim: rgba(75,142,241,0.14);
--status-done:    #3fb97b;           /* Trae 完成绿 */
--status-done-dim: rgba(63,185,123,0.14);
--status-failed:  #ef4444;           /* 失败红，复用 danger-alt 语义 */
--status-failed-dim: rgba(239,68,68,0.12);
--status-warn:    #f59e0b;
```
> 关键决策：**"进行中"从银灰改为蓝色**，让"正在跑"在视觉上跳出来；成功绿统一到 `#3fb97b`（现有 `#10b981/#22c55e/#4ade80` 三处绿收敛为一个）。HEX_COLORS（`shared/theme.ts`）同步补同值字面量，供内联 alpha 拼接。

### 3.3 字号 / 行高（把对话主流整体调松弛 1 档，辅助文字下限抬高）
```css
--text-xs: 11px;  /* 原10：全局辅助文字下限不得小于11 */
--text-sm: 12px;  /* 过程行/标签（Trae 过程行=13，允许12–13） */
--text-base: 13px;
--text-lg: 14px;  /* 步骤标题 */
--text-xl: 15px;  /* AI 叙述正文（Trae 15–16） */
--text-prose: 15.5px; --leading-prose: 1.7;   /* 新增：对话正文体感 */
/* 任务流专用尺度（新增） */
--taskflow-max: 760px;     /* 单栏任务流正文最大宽度，居中（现输入框 860，统一收窄更聚焦） */
--step-row-h: 34px;        /* 单步骤行高，宽松可点 */
--proc-line-h: 26px;       /* 过程行高 */
```

### 3.4 圆角 / 间距 / 阴影 / 动效
- 圆角沿用现有阶梯；**卡片统一 `--radius-2xl 12px`**（对齐 Trae 12px），步骤/过程行本身用 `--radius-md 6px`。
- 阴影去重度：任务流内**默认无阴影**；仅弹层/浮层用：
```css
--shadow-pop: 0 8px 28px rgba(0,0,0,0.45);   /* 替代偏重的 shadow-lg/xl */
/* 任务流内删除 inset-hi、accent-glow 的使用 */
```
- 动效统一三档且更短：出现 160ms、展开 200ms、状态切换 150ms；缓动统一 `cubic-bezier(0.2,0,0,1)`；**running spinner 为唯一无限循环动画**，其余不循环、不发光。尊重 `prefers-reduced-motion`（globals 已有该 media，沿用）。
- **字体去衬线**：任务流与所有工具界面统一 `--font-ui`；`--font-display/heading` 的衬线不在功能 UI 使用（仅可选保留于纯品牌启动页，建议一并改无衬线）。

## 4. 核心组件视觉规范（落地照做）

### 4.1 StepDot 状态圆点（UI-1 原子组件，尺寸 18px）
| 状态 | 形态 | 颜色 | 动效 |
|---|---|---|---|
| pending | 1.5px 空心圆，直径 16 | `--status-pending`，透明度 .7 | 无 |
| running | 实心圆 + 旋转 spinner（lucide `Loader2` 14px）或圆环旋转 | `--status-running` | 匀速 0.9s 线性旋转 |
| done | 圆底 `--status-done-dim` + 对勾（lucide `Check` 12px，描边 2.5） | `--status-done` | 150ms 轻弹入（scale .8→1，仅一次） |
| failed | 圆底 `--status-failed-dim` + `X` 12px | `--status-failed` | 无循环，可一次轻晃 |
- **不使用**发光 box-shadow；对齐方式：圆点列固定宽 22px，与标题左基线对齐。

### 4.2 StepItem 步骤行（UI-1）
- 高 `--step-row-h 34`，左：StepDot；中：标题 14px/`--text-primary` + 括号补充 13px/`--text-tertiary`；右：`ChevronRight` 14px/`--text-tertiary`（展开时旋转 90°）。
- 整行可点，hover 背景 `--bg-hover`、圆角 6；展开区为详情文本（13px、行高 1.6、`--text-secondary`、最多高 240 滚动）。
- failed：标题与原因用 `--status-failed`，展开区默认展开显示错误原因。
- 步骤之间：左侧 22px 圆点列内画 1px 竖向引导线（`--border-subtle`）连接相邻圆点（最后一步不画）。

### 4.3 ProcessLine 工具过程行（UI-2，仿"已执行 N 条命令 〉"）
- 高 `--proc-line-h 26`，13px `--text-secondary`；前置一个 13px 线性小图标（文件/终端/搜索/工具，lucide 线性、1.5 描边）。
- 文案为**聚合摘要**：`已读取 N 个文件`、`已执行 N 条命令`、`调用工具 · {tool}`，同类实时累加计数；右侧 chevron。
- 展开后是该批工具调用的**明细列表**：每行 = 工具名（mono 12px）+ 参数摘要（`--text-tertiary`，超长省略）+ 右侧状态点/✓/✗ + 可再展开 `resultPreview`（≤3 行，超出折叠）。
- running 时该行前置图标处显示 12px 蓝 spinner；完成转静态 ✓ 绿；失败 ✗ 红。**实时插入，不等整轮结束。**

### 4.4 消息流（AI 叙述 / 用户输入）
- AI 消息：**无气泡、无头像框装饰**（现有 32px 灰圆头像可弱化为 18px 线性图标或直接去掉，倾向去掉以贴近 Trae）；正文用 `--text-prose 15.5/1.7`、`--text-primary`。
- 用户消息：轻量胶囊，背景 `--bg-elevated`（不用品牌色描边/品牌淡底），圆角 12，最大宽 75%，右对齐。
- 消息间距 16→**20**，块间距靠留白；`ReasoningBlock（思考过程）`与 ProcessLine 同一视觉语言（小灰行 + chevron），避免出现两种"折叠行"样式。

### 4.5 代码块（UI-3 基础，现有 CodeWindow 升级）
- 保留现有：mac 三色点、语言标签、行号、一键复制、流式后自动折叠。
- 调整：头部背景与正文对比减弱（去重描边）；正文 12.5px/1.7 mono；**补真正语法高亮**（现状只有单色行号，方案见 02 文档 UI-3，原则：轻量、深色友好配色，关键字用低饱和蓝/紫，字符串柔绿，注释灰）。

### 4.6 输入区（Composer）
- 去除玻璃渐变/内高光/辉光：实底 `--bg-elevated` + 1px `--border-default`，focus 时改 `--status-running`（蓝）1px + 极淡外扩 `--status-running-dim`（替代银灰 glow）。
- 圆角 14；发送按钮进行中=红停止方块、空闲=ArrowUp；圆形按钮直径统一 36–40。
- 输入正文 15px；辅助提示行 12px `--text-tertiary`。最大宽 `--taskflow-max 760` 居中。

### 4.7 顶栏 TitleBar（UI-4）
- 高 40 维持；左侧补**两个 18px 线性图标位**（历史/任务列表、搜索——功能映射以 Trae 保留清单为准，不新增后端能力）；中间可放极简当前视图名/菜单文字；右侧窗口三按钮维持。整体 `--bg-surface`、底线 `--border-subtle`、无渐变。

### 4.8 侧栏 Sidebar（UI-4：弱化而非删除，不破坏功能页入口）
- 默认**视觉降权**：宽度 240→**220**，导航项高 38→34、字号 13、激活态从"描边+底色"改为**仅左侧 2px 蓝色指示条 + 透明底**（hover 才显 `--bg-hover`）；分组标题更弱（11px、`--text-disabled`）。
- 提供"收起为图标栏 56px / 完全隐藏"两档（现有 collapsed=64 可收窄到 56；`data-ui-sidebar` 隐藏机制已具备）。**不删任何导航项**（是否裁项由 Trae 保留清单决定）。

### 4.9 底部状态栏 StatusBar（本地算力特色，保留但轻量化）
- 高 24 维持，CPU/内存/GPU/在线是"本地算力终端"的掌控感来源，**保留**；视觉再弱化：11px、`--text-tertiary`，迷你条形 3px、仅超阈值才变色（>50 琥珀、>80 红，现有逻辑保留）。

### 4.10 三态（空 / 载 / 错）
- 复用现有 `EmptyState / LoadingSkeleton / ErrorDisplay`，统一到本规范色与间距：空态用 18px 线性图标 + 14px 次文字，居中、留白；加载用骨架屏或 StepDot spinner，不用三个跳动圆点拟人化（`TypingDots` 替换为 14px 蓝 spinner + "正在思考/执行…"）；错误态用 failed 红 + 可执行的恢复动作，不白屏。

### 4.11 滚动条 / 图标 / 对齐
- 滚动条沿用 5px 细条；图标统一 **lucide 线性、strokeWidth 1.5–2、默认 16–18px**，不混用面性/彩色 emoji 图标（模型/agent 业务 emoji 另议）。
