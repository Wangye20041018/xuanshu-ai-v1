## 四、给 workbuddy 的后端事件增强建议（**非阻塞**，UI 已做兜底）

当前 `TaskStepEvent` / `ToolCallEvent` 可正常驱动 UI，但以下增强能让过程展示更精确：

5. **为 `ToolCallEvent` 补 `callId`**：现无 `callId`，UI 用「从末尾向前找最近一条同名且仍 start 的记录」(LIFO) 配对 start/done/error。并发同名工具时 LIFO 是推断而非精确配对；补 `callId` 后可精确闭合。
6. **补 `runId`（或一次运行的 begin/end 事件）**：现无运行边界标识，UI 靠「是否存在 pending/running 步骤或未闭合工具」推断一次运行的起止；补 `runId` 可精确切分多轮、避免极端时序下两轮被并到一起。
7. **确认 `argsSummary` / `resultPreview` 的截断长度与脱敏规则**：UI 直接展示这两个字段，建议后端统一截断（如 120 / 200 字）并对路径、密钥等做脱敏，UI 侧不再二次裁切。

> 在以上增强落地前，`taskRunStore.ts` 已对「缺 callId / 缺 runId / 丢起始事件」做了兜底（LIFO 配对、活跃边界推断、孤儿终态记录落地），不影响功能可用。

## 五、视觉统一遗留（不在首页主场景，未改，供后续全站统一）

本轮已把**首页对话主场景**（侧栏 / 标题栏 / 底部状态栏 / 首页工具条 / 对话流 / 输入区 / 模型切换器 / 任务时间线 / 代码块）的硬编码紫与辉光清零。以下为排查到的**非主场景**遗留，本轮不改，避免扩大范围：

8. **其他页面零星硬编码紫**：`pages/Model/index.tsx`、`pages/Settings/index.tsx`、`SettingsAuthorization.tsx`、`SettingsSoftwareLibrary.tsx`、`components/TandemPanel.tsx` 仍有少量 `rgba(124,58,237,*)` / `#8b5cf6` 紫色字面量。默认主色 token 已中性化，这些是局部硬编码；如需全站零紫，可逐处替换为 `--status-running` 或中性面 token。
9. **可选背景 / 主题保留**：`globals.css` 中 `:root[data-bg='gradient'] .app-layout` 的紫蓝氛围径向光、以及一套紫黑可选主题（`--bg-base:#13111f` 等）属于用户可切换的背景模式 / 主题，默认不启用，按「不砍功能」原则保留。
10. **顺带修复的既有坏值**：`ModelSwitcher` 原先用 `` `${COLORS.success}77` ``、`` `${COLORS.accent}66` `` 把 `var(--x)` 与十六进制 alpha 直接拼接（会产出无效 CSS、边框实际不生效），本轮改为合法的 `var(--status-*)`。同类「`var()` 拼 alpha」写法在其他组件可能仍有，建议后续统一改用 `HEX_COLORS` 拼接或直接用 `*-dim` token。
